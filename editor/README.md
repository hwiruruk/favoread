# Favorbook 데이터 편집기

브라우저에서 `data.csv`를 직접 편집하고 GitHub에 commit/push까지 처리하는
정적 웹앱입니다. 예스24 Open API(프록시 Worker 경유)로 책 정보
(제목/저자/출판사/표지/상품 링크)를 한 번에 채워 넣을 수 있습니다.

## 어디서 열까

**1) GitHub Pages 사이트로 사용 (권장)**

저장소가 GitHub Pages로 호스팅되고 있으므로 (`https://favorbook.co.kr`),
브랜치가 main에 머지된 후에는 다음 주소로 접속하면 됩니다:

```
https://favorbook.co.kr/editor/
```

머지 전 브랜치에서 미리 보고 싶으면 raw 사이트는 별도 빌드가 필요하므로
아래 로컬 방식을 사용하세요.

**2) 로컬에서 바로 열기**

```bash
cd editor
python3 -m http.server 8765
# 브라우저에서 http://localhost:8765 열기
```

(`file://`로 직접 열어도 동작은 하지만 일부 브라우저가 fetch를 막을 수
있어 정적 서버 사용을 권장합니다.)

## 첫 사용 — 설정

처음 열면 ⚙️ 설정 모달이 자동으로 뜹니다. 다음을 입력하세요:

| 항목 | 값 |
|------|-----|
| GitHub Repo | `hwiruruk/favoread` |
| 발행 브랜치 | `main` — 사이트에 나가는 곳 |
| 드래프트 브랜치 | `draft/editor` (기본값) — 발행 전 작업본을 보관하는 곳. `draft/`로 시작해야 함 |
| CSV 경로 | `data.csv` |
| GitHub Personal Access Token | fine-grained PAT, 이 저장소에 **Contents: Read and write** 권한 |
| 예스24 프록시 Worker URL | `tools/yes24-proxy/` 를 배포한 주소 (책 검색에 필요, API Key는 Worker에만 둠) |
| 커밋 작성자 | `홍길동 <me@example.com>` (선택) |

> 모든 값은 **이 브라우저의 localStorage**에만 저장됩니다. 공용 컴퓨터에서는
> 사용 후 비워두세요. (브라우저 외부로 절대 전송되지 않으며, GitHub
> API에 인증 헤더로만 사용됩니다.)

### GitHub PAT 발급법 (간단)

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**
2. **Generate new token**
3. Repository access → **Only select repositories** → `hwiruruk/favoread` 선택
4. Permissions → Repository permissions → **Contents: Read and write**
5. 생성된 `github_pat_…` 토큰을 설정 모달에 붙여넣기

## 사용 흐름

1. **↻ 불러오기** — GitHub의 최신 `data.csv`를 가져옴 (sha도 함께)
2. 좌측 사이드바
   - 🔍 검색: 한글/영문/책 제목/저자 모두 매칭
   - 필터: `영문명 누락 / 표지 누락 / 연예인 이미지 누락 / 중복 도서` 빠른 점프
   - 중복 도서: 같은 연예인에게 제목이 같은 책이 두 번 들어간 경우(띄어쓰기·문장부호·대소문자 무시). 목록에 `중복` 표시, 책 추가·편집 시 도서명 아래에 바로 경고하고 적용할 때 한 번 더 확인
   - **+ 연예인** 버튼으로 새 인물 추가
3. 연예인 클릭 → 상세 패널
   - 한글/영문/이미지 URL 편집 — 같은 인물이 여러 행에 있으면 저장 시 **모든 행에 일괄 반영**
   - 책 카드: 편집 / 도서 정보 링크 열기 / 삭제
   - **+ 책 추가** 또는 카드의 **편집** → 책 다이얼로그
4. 책 다이얼로그
   - 좌측: 예스24 검색 (제목/저자/ISBN 키워드) 또는 ItemId·ISBN13·URL 직접 조회
   - 도서 정보 칸에 예스24 상품 URL을 붙여넣으면 주소가 정리되고 표지(`image.yes24.com/goods/<ID>/L`)도 채워짐
   - 검색 결과에 `이미 등록`(이 셀럽에게 있음) / `다른 셀럽 N명` 배지 — 제목이 같거나 같은 예스24 상품이면 같은 책으로 판단
   - 결과를 고르면 비어 있는 영문 제목·영문 저자를 자동으로 찾아 채움 (노란 테두리 = 자동 채움, 확인 후 고치면 표시가 사라짐)
   - 기존 책 편집 창을 열면 제목으로 예스24 검색을 미리 해 둠
   - **적용 + 다음 책** — 추가하고 바로 빈 책 추가 창을 다시 엶 (새 책일 때만, Enter는 일반 적용)
   - 예스24 프록시가 설정돼 있지 않으면 ⚙️ 설정 열기 / 예스24 새 탭 검색 버튼을 보여 줌

### 저자명 정리
서점에서 가져온 저자 문자열에는 역할 표기가 붙어 옵니다.
알라딘은 `신영복 (지은이), 김세현 (그림)`, 예스24는 `요아힘 마이어호프 저/박종대 역` 같은 식이에요.
편집기는 **예스24 결과를 적용할 때, 그리고 저자 칸에 직접 붙여넣고 빠져나올 때**
이걸 지은이만 남기고 정리합니다(`cleanAuthorName`).

- `저 · 저자 · 지음 · 지은이 · 공저 · 글 · 글그림 · 쓴이 · 원작` — 꼬리표만 떼고 이름은 남김
- `역 · 역자 · 옮김 · 옮긴이 · 번역 · 편집 · 엮음 · 편저 · 감수 · 사진 · 그림 · 삽화 · 해설` — 그 사람은 아예 뺌
- `,` `/` `;` 로 나뉜 여러 명을 각각 판단하고 `, ` 로 다시 이어 붙임
- 역할 꼬리표 앞에 공백이나 여는 괄호가 있을 때만 떼어냅니다 — `이역` 같은 이름의 끝 글자를
  역할로 잘못 읽지 않기 위해서예요
- **역할이 안 적힌 이름은 뒤에 오는 역할을 따릅니다.** 서점이 같은 역할의 사람을 쉼표로 묶고
  마지막에만 역할을 적기 때문이에요. `패트릭 브링리 (지은이), 김희정, 조현주 (옮긴이)` 에서
  김희정도 옮긴이로 보고 뺍니다
- 역할이 아닌 괄호는 건드리지 않습니다 — `설레다(최민정)` 는 그대로 둡니다
- **불러올 때도 같은 규칙으로 정리합니다.** 예전에 저장된 값에 역할 표기가 남아 있어도
  편집기에는 저자 이름만 보입니다
- 역자만 적혀 있어 남는 이름이 없으면 저자 칸을 덮어쓰지 않고 원문을 그대로 둡니다
   - 검색 결과 클릭 → 우측 폼이 **자동으로 채워짐 + 표지 미리보기**
   - 출처 URL과 코멘트만 추가 입력
5. **📝 드래프트 저장** (`Ctrl+S`) — 사이트에는 안 나갑니다
6. **🚀 발행** — 바뀐 점을 확인하고 사이트에 내보냅니다 (아래 '드래프트와 발행')

## 드래프트와 발행

예전에는 저장 버튼 하나뿐이라, 저장하면 곧바로 main에 커밋되고 사이트가 다시 빌드됐습니다.
작업 중인 내용을 보관만 해 두고 싶어도 사이트에 나가 버렸죠. 지금은 두 단계로 나눴습니다.

| 단계 | 어디에 커밋 | 사이트 |
|------|-------------|--------|
| 📝 드래프트 저장 | 드래프트 브랜치 `draft/editor` | 그대로 |
| 🚀 발행 | 발행 브랜치 `main` (커밋 하나) | 몇 분 뒤 다시 빌드 |

상단 배지로 지금 상태를 보여줍니다.

- `미저장 변경` (노랑) — 아직 어디에도 안 들어간 편집. 새로고침하면 사라집니다
- `드래프트 · 미발행` (파랑) — 드래프트에 보관됐지만 사이트에는 아직 안 나갔습니다. 누르면 발행 창이 열립니다

### 발행 창

**🚀 발행**을 누르면 지금 사이트에 나가 있는 발행본과 비교해서 바뀐 점을 셀럽별로 보여줍니다.

- `새 셀럽` / `셀럽 삭제`
- `＋ 책` 추가, `－ 책` 삭제, `✎ 책` 수정 (어느 칸이 바뀌었는지 괄호로 표시)
- 셀럽 이름을 누르면 그 셀럽으로 이동해 바로 고칠 수 있습니다

커밋 메시지는 `편집기에서 발행 (날짜) — 카리나(에스파) 외 2명 · 책 +3 −1 ✎2` 처럼 자동으로 채워지고,
고쳐 써도 됩니다. 발행하면 드래프트 브랜치는 지웁니다.

- **📝 드래프트만 저장** — 발행하지 않고 보관만
- **드래프트 버리기** — 드래프트 브랜치를 지우고 발행본으로 되돌립니다

### 다른 컴퓨터에서 이어서

드래프트는 브라우저가 아니라 GitHub 브랜치에 있으므로, 다른 컴퓨터·브라우저에서 편집기를 열고
**↻ 불러오기** 하면 드래프트가 이어서 열립니다. 이미 발행됐거나 내용이 발행본과 같은 드래프트
브랜치는 불러올 때 알아서 지웁니다.

### 그새 발행본이 바뀌었으면

드래프트를 만든 뒤 다른 곳에서 발행했거나 봇 PR(영문명 제안 등)이 main에 머지되면,
불러올 때와 발행할 때 그 변경을 드래프트에 **셀럽·책·칸 단위로** 합칩니다.

- 한쪽만 바꾼 칸은 그쪽 값을 씁니다. 다른 셀럽, 같은 책의 다른 칸이면 저절로 합쳐집니다
  (git merge는 줄 단위라 붙어 있는 두 줄을 각자 고쳐도 충돌로 보기 때문에 쓰지 않습니다)
- **같은 책의 같은 칸**을 양쪽이 다르게 고쳤을 때만 충돌입니다. 발행 창 위에 ⚠️ 목록으로
  보여주고, 드래프트 값으로 발행합니다. 발행본 값이 맞으면 그 칸을 고치면 목록에서 빠집니다
- 발행 버튼을 누른 사이에 새 충돌이 생기면 발행을 멈추고 목록을 다시 보여줍니다

### 사이트 재생성이 안 도는 이유

`.github/workflows/update-sitemap.yml`은 `data.csv`가 바뀌면 어느 브랜치든 돌던 워크플로인데,
`branches-ignore: draft/**`를 넣어 드래프트 브랜치에서는 돌지 않게 했습니다. 그래서 드래프트 브랜치
이름은 `draft/`로 시작해야 합니다 (설정에서 안 붙이면 편집기가 붙입니다).

### data.csv만 해당

드래프트는 연예인·책 정보(`data.csv`)에만 적용됩니다. 🔥 핫한 사람, 💬 코멘트 검수, 🔤 영문 제목 검수,
🏷️ 분야 검수는 승인 자체가 '내보내기'라서 지금처럼 각 창의 저장 버튼으로 바로 커밋됩니다.
📚 책 이름 통일 창의 저장은 data.csv를 드래프트에 넣고, 영문 제목 검수 파일은 바로 커밋합니다.
🔤 창은 영문 제목과 저자 영문 이름을 함께 검수합니다 (같은 파일 `data/titles_en.json` 의 `titles` · `authors`, 자세한 건 `tools/TITLES_EN.md`).

## 메인에 고정할 "요즘 핫한 사람" (🔥 핫한 사람)

메인 첫 화면 상단(검색창 바로 아래)에 직접 고른 인물을 한 줄로 고정 노출합니다.

1. 상단 **🔥 핫한 사람** 버튼 → 현재 고정 목록이 뜹니다
2. 아래 검색창에서 이름을 찾아 클릭하면 목록에 추가됩니다
3. 각 줄에서
   - **뱃지** 칸: 사진 위에 붙일 짧은 말머리 (예: `HOT`, `NEW`, `컴백`). 비우면 안 붙습니다
   - **↑ / ↓**: 노출 순서 변경
   - **삭제**: 목록에서 제외 (인물 데이터 자체는 그대로)
4. **💾 GitHub에 저장** — 이 창의 저장 버튼은 `data.csv`와 무관하게
   `data/featured.json` 파일만 따로 커밋합니다

### 몇 명까지 넣나

데스크톱에서 한 줄은 **6명**입니다. 그보다 많이 넣으면 줄이 넘어가고,
**최대 12명(2줄)** 까지만 저장됩니다. 모바일은 2칸, 태블릿은 3칸으로 접힙니다.

### 비워두면

`picks`가 비어 있거나 넣은 이름이 전부 데이터에 없으면
메인에서 이 섹션과 스크롤 탭의 `핫` 버튼이 통째로 사라집니다. 따로 끄는 스위치는 없습니다.

### 파일 형식

편집기 없이 `data/featured.json`을 직접 고쳐도 됩니다.

```json
{
  "title": "🔥 요즘 핫한 사람",
  "subtitle": "지금 가장 화제인 인물을 직접 골라 고정해 뒀어요.",
  "picks": [
    { "name": "카리나(에스파)", "badge": "HOT", "note": "" },
    { "name": "송강", "badge": "NEW", "note": "컴백 기념" }
  ]
}
```

- `name` — `data.csv`의 연예인 이름과 **정확히** 같아야 합니다. 없는 이름은
  빌드할 때 경고를 남기고 조용히 빠집니다
- `badge` — 사진 위 말머리 (선택)
- `note` — 이름 아래 한 줄 설명 (선택). 비우면 그 사람의 책 2권이 자동으로 들어갑니다
- `title` / `subtitle` — 섹션 제목과 설명

사진·권수 카드는 메인의 JS가 `data.json`을 보고 그리고,
`generate.py`가 같은 목록을 크롤러용 정적 링크로도 넣어둡니다.
JSON만 바꾸면 사이트에 바로 반영되고, `generate.py`는 정적 마크업을
맞춰 넣기 위해 돌려주면 됩니다.

## 코멘트 검수 (💬 코멘트 검수)

출처를 보고 **내 메모**를 적어두면, 그걸 AI가 한국어·영어 한 줄로 다듬어 오고,
그 문장을 보고 **승인**하면 사이트에 나가는 창입니다.

```
출처 확인 → 내 메모 (편한 말투)  ← 사람
         → 한국어·영어 한 줄     ← AI 가 다듬음
         → 승인                  ← 사람
```

요약은 출처를 직접 읽은 사람이 제일 정확하고, 그걸 문장으로 다듬는 건 AI가 빠릅니다.
메모는 지워지지 않고 남아서, 나중에 문장을 다시 뽑고 싶을 때 근거가 됩니다.
직접 한국어·영어 칸에 써 넣어도 됩니다. **승인한 항목만** 사이트에 나갑니다.

1. 상단 **💬 코멘트 검수** 버튼 → `data/comments.json`을 읽어 목록을 띄웁니다
2. 카드마다
   - **출처 열기 ↗**: 원문을 새 탭에서 엽니다. 여기서 시작하세요
   - **내 메모**: 읽고 나서 편한 말투로 적습니다. 문장을 다듬을 재료입니다
   - **인용** (파란 줄): 수집기가 출처에서 그대로 떠온 대목. 어디를 볼지 짚어줍니다
   - **앞뒤 문단**: 펼치면 그 앞뒤까지 보입니다
   - **점수**: 추천 이유가 담겼을 법한 정도. 높은 카드가 위로 올라옵니다.
     힌트일 뿐이라 0이어도 쓸 만한 게 있습니다
   - 한국어 / English 칸: AI가 다듬어 온 문장이 들어옵니다. 직접 고쳐도 됩니다
   - 등급 **A**는 원문에 추천 이유가 있는 것, **B**는 관계만 확인된 것
   - **승인 / 보류 / 반려** — 한국어 칸이 비어 있으면 승인되지 않습니다
   - `Ctrl+Enter` (맥은 `Cmd+Enter`): 그 카드를 바로 승인
3. 필터
   - `문장 미작성` — 아직 한 줄을 안 쓴 것만. 메모를 적을 차례입니다
   - `메모만 있음` — 메모는 해뒀고 문장이 아직인 것. **AI에 넘길 줄**입니다
   - `미검수` — 승인·반려한 카드가 빠져서 위에서부터 계속 처리하면 됩니다
4. **💾 GitHub에 저장** — 이 창의 저장 버튼은 `data.csv`와 무관하게
   `data/comments.json` 파일만 따로 커밋합니다

### 메모를 문장으로 — 한꺼번에 채우기

창 아래 **문장 한꺼번에 채우기**를 펼치면 누락 영문 창과 같은 방식으로 씁니다.

1. 필터를 **메모만 있음**으로 두고 **지금 목록 TSV 복사**
   — 키·연예인·도서명·매체·출처·내메모·인용·앞뒤문단이 복사됩니다
2. AI에 맡깁니다. 예를 들면

   > 붙여넣는 표에서 '내메모'를 근거로 책마다 한국어·영어 한 줄씩 써줘.
   > 한국어는 '~했어요' 체로, 끝에 "(출처: 매체명)"을 붙여줘.
   > 메모에 없는 내용은 보태지 말고, 결과는 `키 ⇥ 한국어 ⇥ English` 탭 구분으로만 줘.

3. 돌아온 결과를 붙여넣고 **적용** → 카드에서 읽어보고 **승인**

복사 버튼은 **지금 목록에 보이는 것만** 담습니다. 필터와 검색을 걸어두면
그만큼만 나갑니다.

키는 `연예인|도서명` 그대로여야 합니다. 못 찾은 키는 건너뛰고 몇 건인지 알려줍니다.

연예인 상세 화면의 책 카드에도 검수 상태가 뱃지로 붙습니다
(`💬 코멘트 검수 대기` / `💬 코멘트 승인` / `💬 코멘트 반려`).
검수 창을 한 번 연 뒤부터 표시됩니다.

### 왜 data.csv에 넣지 않나

- 코멘트 칸은 **사람이 직접 쓰는 자리**로 남겨둡니다. 사람이 쓴 값이 늘 우선입니다
- 한/영 두 벌에 등급·근거·검수 상태까지 열로 붙이면 시트가 감당을 못 합니다
- `featured.json`처럼 파일 하나만 따로 커밋하므로 CSV 저장 충돌과 무관합니다

### 파일 형식

```json
{
  "_comment": "…이 파일이 뭔지 설명…",
  "_updated": "2026-09-21",
  "comments": {
    "황소윤(새소년)|거꾸로 사는 재미": {
      "ko": "헌책방에서 우연히 집어 든 책이라고 했어요. …",
      "en": "She said she found it by chance at a used bookstore. …",
      "source": "https://ch.yes24.com/article/details/45760",
      "grade": "A",
      "evidence": "websearch",
      "note": "",
      "status": "pending"
    }
  }
}
```

- 키는 `"<연예인>|<도서명>"`이고 **둘 다 `data.csv`와 정확히 같아야** 합니다.
  맞는 책이 없으면 검수 창에 `데이터에 없는 항목` 뱃지가 붙습니다
  (책 제목을 고쳤을 때 주로 생깁니다)
- `status` — `pending` / `approved` / `rejected`. 반려한 항목은 지우지 않고
  남겨둬서 다음 수집 때 같은 문장을 다시 올리지 않게 합니다
- `note` — 검수할 때 특별히 봐야 할 점. 예를 들어 근거가 기록된 출처가 아니라
  다른 기사에서 나온 경우 여기에 적힙니다
- `evidence` — 그 초안을 무엇으로 뽑았는지 (`websearch` 등)

### 항목은 어디서 오나

`tools/fetch_comments.py` 가 출처를 읽고 채웁니다. GitHub Actions의
**Fetch Book Comments** 워크플로로 돌리며, API 키는 필요 없습니다.
자세한 건 [`tools/COMMENTS.md`](../tools/COMMENTS.md) 참고.

출처 한 건이 10권 넘게 담고 있는 팬 정리 목록은 원문에 추천 이유가 없어
아예 읽지 않습니다. 없는 이유를 지어내면 "출처를 직접 열어 확인할 수 있다"는
사이트의 약속이 깨지기 때문입니다.

### 메모 → AI 다듬기 → 검수

API 키 없이 Claude 대화창으로 다듬습니다.

1. 검수 창의 **내 메모**에 출처를 보고 편한 말투로 적습니다.
   수집기가 아직 항목을 만들지 않은 책은 책 목록의 **💬 메모** 버튼으로 바로 씁니다.
2. **✨ AI 요청 복사**를 누르면 다듬을 메모가 지침과 함께 복사됩니다.
   Claude 대화창(claude.ai)에 붙여넣으면 JSON으로 답이 옵니다.
3. 그 답을 창 아래 **AI 답 붙여넣기** 칸에 그대로 붙여넣고 **붙여넣은 결과 적용**.
   문장이 들어가고 **✨ AI 초안** 표시가 붙습니다.
4. 읽어보고 고치거나 **승인**한 뒤 **💾 GitHub에 저장**하면 사이트에 나갑니다.

- 요청에 담기는 건 메모가 있고 한국어 칸이 빈 미검수 항목, 그리고 AI 문장을 그대로 둔 채
  메모만 바뀐 항목(**메모 바뀜** 표시)입니다. 사람이 고친 문장은 담기지 않습니다.
- 무엇을 보고 언제 다듬었는지는 항목의 `ai` 칸(`memo`·`ko`·`en`·`note`·`at`)에 남습니다.
- 메모를 저장만 해 두면 매일 아침 6시 45분 Claude Code 루틴이 같은 지침으로 다듬어
  `main` 에 커밋합니다 (`tools/COMMENTS.md` 참고). 복사·붙여넣기는 바로 받고 싶을 때만.

## 책 이름 통일 (📚 책 이름 통일)

같은 책인데 셀럽마다 이름이 다르게 적힌 경우를 찾아 하나로 맞추는 창.

- **영문 제목이 갈린 책**: 도서명은 같은데 도서명_en이 줄마다 다른 책
  (예: 첫 여름, 완주 → `First Summer, Wanju` / `First Summer, Completed *`).
  영문 셀럽 페이지는 줄마다 제 값을 써서 같은 책이 사람마다 다른 이름으로 나간다.
  쓸 제목을 고르거나 직접 고쳐 쓰고 **이걸로 통일**을 누르면 그 책의 모든 줄이 같은
  값이 된다. 🔤 영문 제목 검수에서 승인한 값이 있으면 그것도 같이 바꾼다
  (generate.py가 검수 값을 CSV보다 먼저 쓰기 때문).
- **한국어 제목이 다른 같은 책**: 띄어쓰기·부호만 다르거나(어린왕자 / 어린 왕자)
  영문 제목이 같은 책. 책 페이지가 둘로 쪼개지고 "여러 명이 읽은 책"에서 빠진다.
  남길 제목을 고르고 **고른 제목으로 합치기**를 누르면 나머지 줄의 도서명이 바뀐다.
  영문 제목만 같은 묶음은 다른 책일 수도 있으니 표지·저자·출판사를 보고 판단한다.
- 다른 책이면 **다른 책임**을 눌러 목록에서 뺀다 (이 브라우저에 기억).
- 창 아래 **저장**은 data.csv와, 바뀐 게 있으면 `data/titles_en.json`을 차례로 커밋한다.

발행본과의 충돌은 위 '그새 발행본이 바뀌었으면'처럼 편집기가 합칩니다.

먼저 저장한 것입니다. **↻ 불러오기 → 다시 편집 → 저장** 순서로 동기화하세요.
편집기는 미저장 상태에서 페이지를 떠날 때 경고를 표시합니다.

## GitHub 저장 방식 (1MB 한도)

`data.csv`는 **Git Data API**로 저장합니다. blob → tree → commit → ref 순으로 올리고,
결과는 커밋 하나로 떨어져 예전과 같습니다.

예전에는 Contents API(`PUT /contents/{path}`)를 썼는데, 이 API는 본문을 base64로 싣고
**1MB 한도**가 있습니다. data.csv가 799KB를 넘기면서 base64가 1.02MB가 되어 한도를 넘었고,
GitHub이 크기와 무관해 보이는 메시지로 거절했습니다.

```
GitHub 저장 실패 (503): { "message": "Could not create file. Please try again later." }
```

Git Data API의 blob은 100MB까지 받으므로 한동안 여유가 있습니다.

불러오기도 같은 이유로 대비해 뒀습니다. Contents API는 1MB가 넘는 파일의 `content`를
비워서 주는데, 그때는 `GET /git/blobs/{sha}`로 다시 받아옵니다.

충돌 감지는 그대로입니다. 불러올 때의 blob sha를 기억했다가 저장 직전 브랜치 끝에서
같은 파일의 sha와 비교하고, 다르면 저장을 멈춥니다. 커밋을 붙인 뒤 ref는
`force: false`로 옮기므로, 그새 브랜치가 움직였으면 GitHub이 거절합니다.

## GitHub PAT 문제 해결

`Resource not accessible by personal access token` (403):

이 메시지는 **PAT 자체에 권한이 없다**는 뜻입니다. 브랜치 보호 규칙과는 다른
종류의 오류입니다. Fine-grained PAT를 다시 발급하면서:

1. **Repository access** → **Only select repositories** → 대상 저장소를 반드시 체크
2. **Permissions → Repository permissions** → **Contents: Read and write**
3. (조직 저장소라면 조직 관리자가 fine-grained PAT를 허용했는지도 확인)

`main` 브랜치에 직접 푸시가 막혀있다면 (브랜치 보호) 메시지가 다르게 나옵니다.
그 경우는 설정에서 Branch를 다른 작업 브랜치로 바꾸고 GitHub에서 PR로
머지하세요.
