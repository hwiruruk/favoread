# 코멘트 수집 — 출처에서 언급된 대목 떠오기

책 옆에 "왜 이 책을 추천했는지" 한 줄을 붙이기 위한 작업입니다.
세 단계로 나눠져 있습니다.

```
1. 수집   출처를 열어 그 책 이야기가 나온 대목을 원문 그대로 떠온다   ← Actions 가 한다
2. 메모   출처를 확인하고 편한 말투로 적어둔다                       ← 사람이 편집기에서
3. 작성   메모를 한국어·영어 한 줄로 다듬는다                        ← AI 가, 사람이 승인
```

각 단계를 제일 잘하는 쪽에 맡긴 것입니다.

1번은 수백 개 출처를 열어 제목이 나온 자리를 찾고 따옴표 안의 말을 끌어내는
일이라 규칙만으로 됩니다. **그래서 API 키도, 모델도, 돈도 들지 않습니다.**

2번은 출처를 직접 읽은 사람이 제일 정확합니다. 기계 요약은 미묘하게 어긋나고,
그 어긋남은 읽어본 사람만 알아챌 수 있습니다.

3번은 말투를 고르고 한국어·영어를 맞추는 일이라 AI가 빠릅니다.
다만 메모에 없는 내용을 보태지 않게 하고, 나간 문장은 사람이 승인합니다.

`quote` 와 `memo` 가 남는 것도 이래서입니다. 나중에 이 문장이 어디서 왔는지
되짚을 수 있고, 검수할 때 출처를 일일이 열지 않아도 판단이 섭니다.

## 1단계 — 수집 돌리기

GitHub 웹에서 **Actions → Fetch Book Comments → Run workflow**.
넣어둘 Secret은 없습니다.

| 입력 | 뜻 |
|------|-----|
| `limit` | 이번에 읽을 출처 수. **처음엔 10으로 해서 결과를 먼저 보세요** |
| `dry_run` | 켜면 결과만 찍고 파일은 안 바꿉니다. 첫 실행은 켜두는 걸 권합니다 |
| `refresh` | 지난번에 못 읽은 출처도 다시 조회 |
| `max_books` | 한 출처가 이 권수를 넘게 담고 있으면 건너뜁니다 (기본 3) |

결과는 PR로 올라옵니다. 바뀌는 파일은 `data/comments.json` 하나입니다.

로컬에서 돌리려면 (설치할 것 없음, 표준 라이브러리만 씁니다):

```bash
python3 tools/fetch_comments.py --limit 10 --dry-run
```

## 2·3단계 — 메모하고 문장으로 다듬기

편집기(`/editor/`)에서 **💬 코멘트 검수** 창을 엽니다.
필터를 **문장 미작성**으로 두면 손볼 것만 뜹니다. 점수가 높은 것부터 올라옵니다.

카드의 **출처 열기**로 원문을 확인하고, **내 메모**에 편한 말투로 적어둡니다.
인용은 어디를 볼지 짚어주는 용도라 메모를 쓸 때 참고만 하면 됩니다.

메모를 저장하면 AI가 문장을 써서 커밋합니다(아래 **3단계 자동화**).
1~3분 뒤 **↻ 새로 불러오기**를 누르고 필터를 **AI 초안 (승인 전)**으로 두면
AI가 쓴 것만 뜹니다. 읽어보고 **승인**하면 끝입니다.

자동 작성을 쓰지 않을 때는 필터를 **AI 작성 대기**로 두고 **지금 목록 TSV 복사** →
AI에 맡긴 결과를 `키 ⇥ 한국어 ⇥ English` 로 붙여넣어도 됩니다.

메모는 지워지지 않고 `memo` 칸에 남습니다. 나중에 문장을 다시 뽑고 싶을 때
근거가 되고, 누가 무엇을 보고 썼는지도 남습니다.

키는 `연예인|도서명` 그대로여야 합니다.

## 3단계 자동화 — 메모를 저장하면 AI가 문장을 쓴다

편집기에서 **내 메모**(초안)를 적고 저장하면 GitHub Actions의
**Draft Comments with AI** 워크플로(`.github/workflows/draft-comments.yml`)가 자동으로 돕니다.

```
메모 저장(편집기) → data/comments.json 커밋
  → 워크플로: 출처 링크를 Chromium 으로 열어 PDF로 뜸
  → Claude Code(구독 토큰)가 PDF + 메모 + 인용을 읽고 한국어·영어 한 줄을 씀
  → ko·en 에 채우고 바로 커밋 (status 는 pending 그대로)
→ 편집기에서 ↻ 새로 불러오기 → 읽어보고 승인
```

- API 요금은 들지 않습니다. Claude 구독(Pro/Max) 토큰으로 돌고, 사용량은 구독 한도에서 빠집니다
- 준비 (한 번만)
  1. 내 컴퓨터 터미널에서 `claude setup-token` 을 실행하고 브라우저에서 로그인합니다
  2. 화면에 나온 토큰(`sk-ant-oat…`)을 복사합니다
  3. 저장소 Settings → Secrets and variables → Actions → New repository secret,
     이름은 `CLAUDE_CODE_OAUTH_TOKEN`, 값에 토큰을 붙여넣습니다
  - 없으면 경고만 남기고 건너뜁니다
- 대상: `memo` 가 있고 미검수(pending)이면서
  `ko` 가 비었거나, AI가 쓴 뒤 메모를 고친 항목(`ai_memo` ≠ `memo`)
- 문장을 손으로 고치면 사람 것으로 봅니다(`ai_memo` 삭제). 메모를 바꿔도 덮어쓰지 않습니다.
  다시 쓰게 하려면 한국어 칸을 비우고 저장하세요
- 출처를 PDF로 못 뜨면(유튜브·로그인 벽·20MB 초과·오류) 본문 텍스트나 자막으로,
  그것도 없으면 메모와 인용만으로 쓰고 `ai_note` 에 그렇게 적습니다
- 한 번에 최대 20건. 수동 실행(Run workflow)에서 `limit`·`key`·`force`·`dry_run` 을 고를 수 있습니다
- 워크플로 안에서는 세 단계로 나뉩니다. `draft_comments.py prepare` 가 PDF와 지시문
  (`.draft-work/INSTRUCTIONS.md`)을 만들고, Claude Code 가 그걸 읽어 `results.json` 을 쓰고,
  `draft_comments.py apply` 가 검사해서 comments.json 에 넣습니다.
  준비한 사이에 편집기에서 메모를 또 고쳤거나 승인·반려한 항목은 반영하지 않습니다

AI가 쓴 항목에 붙는 칸

| 칸 | 뜻 |
|----|----|
| `evidence` | `ai-pdf` 출처 PDF를 읽음 / `ai-text` 본문·자막을 읽음 / `ai-memo` 출처를 못 읽어 메모만 봄 |
| `ai_memo` | AI가 문장을 쓸 때 본 메모. 지금 메모와 다르면 다시 씁니다 |
| `ai_note` | AI가 남긴 검수 참고 (메모와 출처가 어긋남, 출처 확인 못 함 등) |

편집기 저장은 최신 파일을 받아 **이번에 손댄 항목만** 덮어쓰므로,
워크플로가 그새 커밋한 다른 항목의 문장이 지워지지 않습니다.

로컬에서 돌리려면 (Claude Code 가 있으면 추가 비용 없음):

```bash
pip install playwright && python3 -m playwright install chromium
python3 tools/draft_comments.py prepare --list     # 대상만 보기
python3 tools/draft_comments.py prepare --limit 3  # .draft-work/ 에 PDF·지시문 준비
claude ".draft-work/INSTRUCTIONS.md 를 읽고 그대로 해줘"
python3 tools/draft_comments.py apply --dry-run    # 결과만 찍기
python3 tools/draft_comments.py apply              # comments.json 에 반영
```

## 무엇을 뽑아 오나

책 제목이 나온 문장을 찾고, 앞뒤 두 문장씩 붙여 한 덩어리로 봅니다.
그 안에 따옴표로 묶인 발언이 있으면 그걸 `quote` 로, 없으면 제목이 들어간
문장을 `quote` 로 둡니다. 덩어리 전체는 `context` 에 들어갑니다.

`score` 는 추천 이유가 담겼을 법한 정도입니다. '인상', '위로', '계기',
'꼽았' 같은 말이 몇 개나 있는지 세고 따옴표 발언이 있으면 더합니다.
**점수는 힌트일 뿐 판정이 아닙니다.** 0이어도 쓸 만한 게 있고,
높아도 엉뚱한 문장이 잡힐 수 있어서 읽어보고 정해야 합니다.

책 제목이 그 자체로 따옴표에 싸인 경우(`"구의 증명"이다`)는 발언으로 보지
않습니다. 제목에 부제가 붙어 있으면 부제를 뗀 형태로도 찾습니다.

## 왜 이유를 지어내지 않나

사이트는 "모든 리스트는 직접 열어서 확인할 수 있는 출처에서 나왔다"고
말하고 있습니다. 그럴듯한 이유를 채워 넣으면 그 말이 깨집니다.
수집 단계에서 원문을 그대로만 옮기는 것도, 문장 쓰기를 사람 손에 남겨둔 것도
같은 이유입니다.

`max_books` 가 있는 것도 마찬가지입니다. 한 출처가 수십 권을 담고 있으면
팬이 정리한 목록이고, 거기엔 애초에 이유가 없습니다.

## 출처별로 되는 것과 안 되는 것

| 출처 | 상태 |
|------|------|
| 기사·매거진·블로그·커뮤니티 | 본문을 그대로 읽습니다. 가장 잘 나옵니다 |
| 유튜브 | 자막을 받아옵니다. 자막이 없는 영상은 제목·설명만 보고, 그것도 없으면 건너뜁니다 |
| X(트위터)·인스타그램·틱톡 | 로그인 벽이라 건너뜁니다 (`misses` 에 `login-wall`) |

## 파일 형식

```json
{
  "_comment": "…이 파일이 뭔지 설명…",
  "_updated": "2026-09-21",
  "comments": {
    "홍경|여수의 사랑": {
      "ko": "",
      "en": "",
      "memo": "",
      "quote": "20대를 통과하는 한 사람으로서 삶이 얼마나 불안정하고 유약한가 생각했다",
      "context": "배우 홍경은 최근 인터뷰에서 「여수의 사랑」을 꼽았다. 그는 …",
      "source": "https://cine21.com/news/view?mag_id=…",
      "outlet": "씨네21",
      "grade": "",
      "score": 3,
      "evidence": "fetch",
      "note": "",
      "status": "pending"
    }
  },
  "misses": {
    "https://x.com/…": "login-wall"
  }
}
```

- 키는 `"<연예인>|<도서명>"`이고 **둘 다 `data.csv`와 정확히 같아야** 합니다
- `grade` — 문장을 쓰면서 정합니다. `A` 는 원문에 이유가 있는 것,
  `B` 는 관계만 확인된 것
- `memo` — 사람이 출처를 보고 적어둔 메모. 문장을 다듬는 재료이자
  그 문장이 어디서 왔는지의 기록입니다
- `evidence` — `fetch` 는 출처를 직접 읽은 것, `websearch` 는 그 전에
  검색 결과로 만든 초안입니다
- `misses` — 다음 실행 때 건너뛸 출처. 편집기에서 저장해도 지워지지 않습니다

## 이미 항목이 있는 출처는 건드리지 않습니다

한 출처의 책이 전부 `comments` 에 들어 있으면 그 출처는 아예 읽지 않습니다.
사람이 쓴 문장을 덮어쓰지 않기 위해서입니다.
다시 뽑고 싶으면 `data/comments.json` 에서 그 항목을 지우고 돌리세요.
