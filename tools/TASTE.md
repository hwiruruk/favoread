# 독서 취향 통계

셀럽 페이지(한국어·영문)에 📊 독서 취향을 붙입니다. 분야·키워드·작가·번역서 비율·출간 시기·분량·출판사를 세어
믿을 만한 것만 몇 줄로 보여줍니다.

```
1. 책 정보 수집    예스24 API에서 번역서 여부·출간일·쪽수·시리즈를 받아 data/bookinfo.json 에 저장   ← Fetch Book Info 액션
2. 분야·키워드 수집 ISBN으로 국립중앙도서관·도서관 정보나루에서 KDC 분류와 키워드를 받아
                   data/subjects.json 에 저장 (1단계가 먼저 돼 있어야 한다)                       ← Fetch Book Subjects 액션
3. 통계 계산       generate.py 가 빌드 때 tools/taste.py 로 계산                                    ← 사이트 갱신 때 저절로
```

작가와 출판사는 `data.csv` 에 이미 있어서 1·2단계 없이도 나옵니다.

## 분야·키워드 (국립중앙도서관 + 도서관 정보나루)

예스24에는 책별 분야가 없어서 공공 도서관 데이터를 씁니다. 책마다 이렇게 받습니다.

1. 예스24 상품 번호로 ISBN13을 받는다 (제목 검색이 아니라 엉뚱한 책이 붙지 않는다)
2. 국립중앙도서관 ISBN 서지정보: KDC 분류번호, 부가기호 (출판사가 적은 것이라 KDC가 빈 책이 많다)
3. 국립중앙도서관 소장자료 검색: 청구기호. 국내 출간 도서는 모두 납본되고 사서가 분류하므로, 청구기호 앞의 KDC(예: 813.7)를 쓴다
4. 도서관 정보나루 도서 상세: 공공도서관이 정리한 KDC 분류번호와 분류 이름(예: 문학 > 한국문학 > 소설)
5. 도서관 정보나루 키워드: 책에서 뽑은 단어와 가중치

분류는 정보나루 → 소장자료 청구기호 → ISBN 서지정보 KDC → 부가기호 끝 세 자리 순서로 고릅니다. 키는 하나만 있어도 돕니다.
국립중앙도서관은 KDC가 빈 책이 많아(첫 실행 156권 중 105권) 부가기호로 대신하는데, 부가기호는 문학을
810(한국문학)·840(영미문학)처럼 나라까지만 알려줘서 소설인지 에세이인지 모릅니다. 그런 책은 분야 통계에서 빠지고,
정보나루 분류(대개 813.7처럼 자세함)가 채워지면 들어갑니다.
한 기관이 막히면(정보나루 키 승인 전, 하루 한도 초과 등) 그 기관만 빼고 계속 받습니다.
빠진 기관 정보는 다음 실행 때 그 기관 것만 마저 받습니다.

### 인증키 받기 (둘 다 무료)

| Secret 이름 | 어디서 | 메모 |
|------|------|------|
| `NL_API_KEY` | 국립중앙도서관 Open API (www.nl.go.kr) — 회원가입 후 Open API 인증키 신청 | ISBN 서지정보와 소장자료 검색에 같이 쓴다 |
| `NL_SEARCH_KEY` | 소장자료 검색 키가 따로 발급됐을 때만 | 없으면 `NL_API_KEY` 를 쓴다. 키 오류가 나면 로그에 이 Secret 을 넣으라고 나온다 |
| `LIBRARY_API_KEY` | 도서관 정보나루 (www.data4library.kr) — 회원가입 → 마이페이지 → 인증키 신청 | 승인까지 하루쯤 걸릴 수 있다. 하루 호출 한도가 있다 |

GitHub 저장소 Settings → Secrets and variables → Actions → New repository secret 에 위 이름 그대로 넣습니다.
정보나루는 책 한 권에 2번 부르므로 워크플로는 하루 200권씩만 받습니다. 1,600권이 넘으니 처음엔 며칠에 걸쳐 채워집니다.
머지 안 한 지난 PR이 있으면 거기서 이어서 받으니, PR은 쌓인 뒤 한 번에 머지해도 됩니다.

### 애매한 책은 편집기에서 직접 (🏷️ 분야 검수)

분류번호가 `810`(한국문학)·`879`(포르투갈문학)처럼 나라만 있어 소설인지 에세이인지 모르는 책,
기관끼리 분류가 다른 책, 도서관 데이터가 없는 책은 편집기 상단 **🏷️ 분야 검수** 창에 모입니다.
분야 버튼을 누르고 저장하면 `data/genres.json` 에 커밋되고, `taste.py` 는 이 값을 자동 분류보다 먼저 씁니다.
'통계에서 뺌'(`제외`)을 고르면 그 책은 분야 통계에 들어가지 않습니다.
소장자료 청구기호를 아직 조회하지 않은 책은 다음 수집 때 저절로 풀릴 수 있어 목록에 넣지 않고 '자동 조회 대기'로 셉니다.
`subjects.json` 에 직접 쓰지 않는 이유: 수집 워크플로 PR이 그 파일을 통째로 갈아 끼우기 때문입니다.

분야 목록은 `tools/taste.py` 의 `GENRE_EN` 과 `editor/app.js` 의 `GENRES` 두 곳에 있습니다 (같이 고칠 것).
KDC → 분야 규칙도 `genre()` 와 `kdcGenre()` 두 곳에 있습니다.

### 나오는 문장

- 주로 읽는 분야: 소설 12권, 에세이 6권, 인문 4권 (분야를 아는 30권 중). — 분야를 아는 책이 5권 이상, 전체의 70% 이상일 때 늘 나온다
- 소설 비중이 사이트 평균보다 높아요 — 3권 이상이면서 평균보다 20%p 이상 높을 때
- 책 키워드로 보면: 상실, 기억, 바다. — 그 셀럽의 책 2권 이상, 그리고 키워드가 있는 그 셀럽 책의 10% 이상에
  나온 키워드만, 최대 5개. 영문 페이지에는 안 나온다.
  정보나루 키워드는 책 소개글에서 뽑은 단어라 잡음이 많아서 이렇게 거른다.
  1. 한글 2~8자 낱말만 남긴다 (다른 책 제목처럼 띄어쓰기가 있는 것, 숫자·영문·한자는 뺀다)
  2. 사이트에 있는 작가·출판사 이름 낱말은 뺀다 (하루키, 오웰, 민음사, 문학동네)
  3. `_KW_STOP` 의 상투어는 뺀다 (소설·작가 같은 책 용어, 세상·이유·시작 같은 소개글 상투어, 수상·베스트셀러 같은 홍보 용어)
  4. 사이트 책 15% 넘게 나오는 흔한 단어는 뺀다 (지금은 사람·사랑)
  어색한 단어가 보이면 `tools/taste.py` 의 `_KW_STOP` 에 넣으면 된다.

## 나오는 조건 (tools/taste.py 맨 위 상수)

| 조건 | 기준 |
|------|------|
| 책 수 | 5권 미만이면 아무것도 안 나옵니다 |
| 번역서·출간 시기·분량 | 그 정보가 확인된 책이 5권 이상이고 전체의 70% 이상 |
| 위 세 가지가 말해지려면 | 사이트 전체 평균보다 25%p 이상 차이. 최근 출간은 50% 이상, 분량은 해당 책이 50% 이상 |
| 작가 | 서로 다른 작품 2권 이상 (한 권짜리 작가는 안 나옴, 1권·2권, 상·하는 1작품, 최대 3명) |
| 출판사 | 3권 이상이면서 비중 30% 이상 |
| 참고 코멘트 | 꼽힌 작가·출판사의 책 중 코멘트가 붙은 첫 권을 한 줄 덧붙임 |

어느 것도 조건을 못 채우면 섹션 자체가 안 나옵니다. "두꺼운 책" 기준은 500쪽 이상, "가벼운 분량"은 250쪽 이하입니다.
"최근"은 올해 포함 2년입니다. 고전의 개정판은 출간일이 최근으로 잡히니, 최근 출간은 평균보다 훨씬 높을 때만 말합니다.

## 자동으로 도는 방식

`Fetch Book Info` 워크플로가 매일 한 번 깨어나 정보를 모르는 책을 셉니다.
**10권 이상 모였을 때만** 예스24를 조회하고 PR을 올립니다. 기준은 워크플로의 `MIN_BATCH` 입니다.
새 셀럽이 들어와도 똑같습니다. 그 사람 책의 정보가 채워지면 다음 빌드에서 취향이 붙습니다.
표지가 예스24가 아닌 책은 조회하지 않고 통계에서 빠집니다.

손으로 돌리려면 Actions → Fetch Book Info → Run workflow (권수와 상관없이 조회).
필요한 Secret은 `YES24_PROXY` 또는 `YES24_API_KEY` 입니다 (책등 워크플로와 같은 값).

PR을 머지하면 사이트 갱신 워크플로가 돌아 페이지에 반영됩니다.

## 첫 실행 뒤에 확인할 것

예스24의 `series`(시리즈 번호)는 받아 두지만 작품을 묶는 데 쓰지 않습니다. 출판사 전집(민음사 세계문학전집 61권)이나
작가 모음(한강 작품 전부)까지 한 시리즈로 들어 있어서, 서로 다른 책이 한 작품으로 묶이기 때문입니다.

번역서 판정은 예스24 응답의 `originalTitle`(원제)이 있거나 `originalTranslation` 이 예/Y 류일 때 번역서로 봅니다.
문서에 값의 형태가 자세히 나와 있지 않아서, 판정에 쓴 원값을 `bookinfo.json` 에 같이 남겨 둡니다.
첫 PR에서 국내서·번역서 몇 권을 훑어보고 틀리면 `tools/fetch_bookinfo.py` 의 `to_info()` 를 고치세요.

## 틀린 값 고치기

`data/bookinfo.json` 을 직접 고치면 됩니다. 이미 있는 책은 다시 조회하지 않으므로 덮어쓰이지 않습니다.

분야가 틀렸으면 `data/subjects.json` 에서 그 책의 `kdc` 를 고치면 됩니다. 키워드도 지우거나 고쳐도 됩니다.

로컬에서 확인: `python3 tools/fetch_bookinfo.py --count`, `python3 tools/fetch_subjects.py --count`
