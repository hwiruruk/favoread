# 책등 이미지 채우기 — 따라 하기

책장에 **진짜 책등 사진**을 채워 넣는 작업입니다.
터미널도, 프로그램 설치도 필요 없어요. **GitHub 웹에서 버튼 세 번**이면 됩니다.

준비(딱 한 번) 5분 + 실행 2분이면 끝납니다.

---

## 0. 지금 왜 필요한가

예스24는 표지와 **같은 번호**로 책등 사진을 줍니다.

```
표지  image.yes24.com/goods/91901136/L
책등  image.yes24.com/goods/91901136/side       ← 뒤만 side 로 바꾼 것
```

그래서 표지를 **예스24에서 가져온 책**은 자동으로 책등이 나옵니다.
문제는 표지를 **알라딘에서 가져온 책** — 예스24 번호를 모릅니다.

| | 권수 | 상태 |
|---|---|---|
| 표지가 예스24 | 204 | 이미 책등 나옴 |
| 표지가 알라딘 | 942 | **이 작업으로 찾습니다** |
| 링크 없음 | 28 | 색 책등으로 남음 |

못 찾은 책은 제목으로 만든 **색 책등**이 대신 나옵니다. 화면이 비지는 않아요.

---

## 1. 준비 — 열쇠 두 개 넣어두기 (한 번만)

### 1-1. 열쇠 값 복사하기

이미 갖고 계신 값입니다. **편집기에서 그대로 복사**하면 돼요.

1. https://favorbook.co.kr/editor/ 접속
2. 오른쪽 위 **⚙️** 클릭
3. 두 칸의 값을 복사해 메모장에 붙여 둡니다
   - **알라딘 TTBKey** → `ttb...` 로 시작하는 긴 글자
   - **예스24 프록시 Worker URL** → `https://....workers.dev`

> 예스24 칸이 비어 있으면 [`tools/yes24-proxy/README.md`](./yes24-proxy/README.md) 를 먼저 보세요.
> 10분이면 만들 수 있습니다.

### 1-2. GitHub에 넣기

1. https://github.com/hwiruruk/favoread 접속
2. 위쪽 **Settings** 탭 클릭
3. 왼쪽 메뉴에서 **Secrets and variables** → **Actions** 클릭
4. 초록색 **New repository secret** 버튼 클릭
5. 아래 두 개를 **하나씩** 넣습니다 (하나 넣고 저장 → 다시 New 버튼)

| Name 칸에 | Secret 칸에 |
|---|---|
| `ALADIN_TTB_KEY` | 아까 복사한 알라딘 키 |
| `YES24_PROXY` | 아까 복사한 `https://....workers.dev` |

> 이름은 **대문자와 밑줄까지 똑같이** 적어야 합니다. 복사해서 붙여 넣으세요.
> 한 번 저장하면 다시 볼 수 없지만, 필요하면 같은 이름으로 덮어쓰면 됩니다.

---

## 2. 실행 — 먼저 연습으로

1. 저장소 위쪽 **Actions** 탭 클릭
2. 왼쪽 목록에서 **Fetch Book Spines** 클릭
3. 오른쪽 **Run workflow ▾** 버튼 클릭
4. 이렇게 두고 초록색 **Run workflow** 클릭

   | 칸 | 값 |
   |---|---|
   | 이번에 조회할 책 수 | `30` |
   | 연습 모드 | **체크됨** (기본값 그대로) |
   | 나머지 둘 | 체크 안 함 |

5. 잠깐 기다리면 목록에 노란 점 → 초록 체크로 바뀝니다
6. 그 줄을 클릭 → **spines** → **책등 찾기** 를 펼쳐서 결과를 봅니다

읽는 법은 이렇습니다.

```
[3/30] ✓ 소년이 온다 — 13137546 (isbn)      찾았다
[7/30] – 어떤 책 — 상품은 찾았지만 책등 없음   예스24에 책등 사진이 없는 책
[9/30] ✗ 다른 책 — 검색 결과에 제목이 맞는 책이 없음
[9/30] ⚠ 또 다른 책 — ... (기록 안 함)        잠깐 실패. 다음에 다시 시도함
```

맨 아래 줄에 **몇 권 찾았는지** 요약이 나옵니다.

> ⚠ 가 계속 나오고 **"일시적 오류가 8번 연달아 났습니다"** 로 멈추면
> 1단계의 열쇠 값이 잘못됐을 가능성이 큽니다. 이름 철자와 값을 다시 확인하세요.

---

## 3. 진짜로 돌리기

연습 결과가 괜찮으면 같은 자리에서 다시 **Run workflow**, 이번엔

| 칸 | 값 |
|---|---|
| 이번에 조회할 책 수 | `0` (= 전부) |
| 연습 모드 | **체크 해제** |

942권이라 **20~30분쯤** 걸립니다. 창을 닫아도 서버에서 계속 돌아갑니다.

끝나면 **Pull requests** 탭에 `chore: 책등 이미지 URL 갱신` 이라는 PR이 올라옵니다.
열어서 **Files changed** 를 보면 `data/spines.json` 한 파일만 바뀌어 있어요.

- `spines` — 찾은 책등 목록
- `misses` — 못 찾은 책과 그 이유

**Merge pull request** 를 누르면 끝입니다.
머지하면 사이트가 자동으로 다시 만들어져서 책장에 진짜 책등이 나옵니다.
(몇 분 걸려요.)

---

## 4. 나중에 또 돌릴 때

책을 새로 추가한 뒤 같은 방법으로 다시 돌리면 됩니다.
**이미 찾은 책은 건너뛰니까** 새로 들어온 책만 조회해서 금방 끝나요.

나머지 두 칸은 이럴 때 씁니다.

| 칸 | 언제 |
|---|---|
| 지난번에 못 찾은 책도 다시 조회 | 예스24에 나중에 책등이 올라왔을 수 있을 때 |
| 이미 찾은 책등이 살아있는지 확인 | 책등이 깨져 보일 때 |

### 잘못 찾은 책이 있으면

`data/spines.json` 의 `spines` 에서 그 줄을 지우면 됩니다.
그 책은 색 책등으로 돌아가요. GitHub 웹에서 연필 아이콘으로 바로 고칠 수 있습니다.

---

## 참고 — 컴퓨터에서 직접 돌리기

파이썬을 쓸 줄 아시면 이렇게도 됩니다.

```bash
export ALADIN_TTB_KEY=ttb...
export YES24_PROXY=https://<worker>.workers.dev
python3 tools/fetch_spines.py --limit 30 --dry-run   # 연습
python3 tools/fetch_spines.py                        # 전체
python3 generate.py                                  # 사이트에 반영
```

| 옵션 | 뜻 |
|---|---|
| `--limit N` | 이번에 조회할 책 수 (0=전부) |
| `--dry-run` | 파일에 쓰지 않고 결과만 |
| `--refresh` | 못 찾은 책 다시 조회 |
| `--recheck` | 찾은 책등이 살아있는지 재확인 |
| `--sleep SEC` | 호출 간 대기 (기본 0.34초) |

## 참고 — 어떻게 찾나

```
알라딘 링크의 ItemId ─(알라딘 API)→ ISBN13
ISBN13 ─(예스24 API)→ 예스24 표지 주소 → 번호 → 책등 주소
```

ISBN으로 못 찾으면 **제목+저자로 검색**하고, 괄호 안 부제와 문장부호를 턴 뒤
제목이 맞을 때만 받아들입니다. 마지막으로 **책등 사진이 진짜 있는지 확인**하고 기록해요.

연결이 잠깐 끊겨서 생긴 실패는 **기록하지 않습니다.** 다음에 다시 시도해요.
그런 실패까지 '없음'으로 적으면 그 책이 영영 색 책등으로 남기 때문입니다.

### `data.csv` 는 건드리지 않습니다

편집기가 CSV를 자기 방식대로 다시 쓰기 때문에, 이 결과를 CSV에 넣으면
다음에 편집기로 저장할 때 날아갑니다. 그래서 `data/spines.json` 이라는
**따로 파일**에 둡니다.

`generate.py` 가 이 파일을 읽어서 책장 페이지에 박고, `data.json` 의 각 책에
`spineUrl` 을 실어 보냅니다. 카드뉴스와 함께 읽기 카드는 그걸 그대로 씁니다.
`data/spines.json` 이 푸시되면 **Update Site Data 워크플로가 알아서 다시 빌드**합니다.
